# 시뮬레이션 진행 방식

Python으로 만든 게임 엔진이 매치를 진행합니다. 엔진이 남긴 플레이 기록은 웹에서 재생할 수 있습니다. AI 에이전트가 무엇을 보고 어떻게 행동을 제출하는지부터, 그 결과가 다음 매치에 어떻게 이어지고 웹에서는 어떻게 재생되는지까지 설명합니다.

## 1. 어떤 라이브러리와 프레임워크를 사용하고, 무엇을 참고했나요?

시뮬레이션은 Python으로 작성했습니다. 참가자별 관측과 행동 요청에는 [Concordia](https://github.com/google-deepmind/concordia)를, 대화와 비공개 메시지 관리에는 [ChatArena](https://github.com/Farama-Foundation/ChatArena)를 사용했습니다. 웹은 [React](https://react.dev/)로 구성하고, 재생 버튼과 탭 같은 조작 요소에는 [Astryx](https://astryx.atmeta.com/)를 사용했습니다. 픽셀 아트 세트장과 캐릭터는 브라우저의 Canvas로 그립니다.

게임 규칙은 시즌 3 본편과 회차별 규칙 정리를 바탕으로 구현했고, 세트장과 피스 디자인은 [넷플릭스 공식 예고편](https://about.netflix.com/ko/news/the-devils-plan-dead-again-main-trailer)을 참고했습니다. 캐릭터가 한 공간에서 이동하고 대화하는 모습을 관전 화면으로 보여주는 방식은 [Generative Agents 연구(Park 외, 2023)](https://hci.stanford.edu/publications/paper.php?id=482)를 참고했습니다.

## 2. 게임 엔진과 AI 에이전트는 어떻게 연결하나요?

양자택일, 무거운 13, 미스터리 거래소, 러시안 룰렛은 각각 별도의 Python 모듈로 구현했습니다. 공통 실행기 `Match`가 행동을 요청하고 제출을 기록하면, 각 게임의 코드가 승점, 벌점, 주문 체결과 최종 순위를 계산합니다.

ChatArena의 `MessagePool`은 참가자마다 볼 수 있는 메시지를 골라냅니다. Concordia는 참가자별 에이전트와 관측 메모리를 두고, 그 참가자가 본 사건과 현재 목표를 바탕으로 모델에 다음 행동을 요청합니다. 잔디 깔기에서는 ChatArena의 `Arena`와 `Environment`로 차례와 타일 배치도 진행합니다.

## 3. 모델은 어떻게 호출하고 응답은 어떻게 처리하나요?

같은 에이전트 코드에서 Codex CLI, OpenAI Responses API, Claude Code, Claude API 중 하나를 선택할 수 있습니다. 텍스트 요청에 쓸 모델과 이미지가 첨부된 요청에 쓸 모델도 따로 지정할 수 있습니다. 예를 들어 협상은 기본 모델이 맡고, 큐브 세기에서 네 방향의 이미지가 첨부된 요청만 이미지용 모델로 보낼 수 있습니다.

모델 응답은 JSON으로 받습니다. 예를 들어 양자택일 선택 1에서는 `{"action":"보험금","note":"감옥동에 갈 가능성이 높다고 봤습니다."}`처럼 선택과 근거를 함께 제출합니다. 엔진은 제출한 카드를 실제로 보유하고 있는지, 타일이 이미 놓인 칸과 겹치는지처럼 해당 시점의 규칙을 검사합니다. 공통 실행기에서 유효하지 않은 행동이 들어오면 해당 제출을 비공개로 기록하고, 그 단계에 정해 둔 기본 행동으로 진행합니다.

## 4. 참가자마다 다른 정보는 어떻게 전달하나요?

각 이벤트에는 공개 여부나 수신자 목록을 `visible_to`로 기록합니다. 모델에 행동을 요청할 때는 참가자 ID, 페르소나, 목표, 단계별 규칙과 선택지에 그 참가자가 볼 수 있는 최근 사건과 대화를 붙입니다. 양자택일 선택 5에서 정보를 고른 참가자에게만 선택 6~8의 규칙을 미리 전달하는 것도 이 방식입니다.

메인홀에서는 이동 결과를 기록해 누가 복도나 네 개의 룸에 있는지 관리합니다. 룸 발언은 발언 당시 그 룸에 있던 참가자에게 전달합니다. 귓속말은 같은 장소에 있는 상대 한 명에게만 보낼 수 있습니다. 룸 초대의 안건은 초대받은 사람에게 전달되고, 수락하면 그 룸으로 이동합니다.

## 5. 동시 선택과 순서가 있는 행동은 어떻게 처리하나요?

단말기 투표나 무거운 13의 카드·칩 제출에서는 판세를 고정한 채 모델에 병렬로 요청합니다. 모두 같은 시점에서 판단하며 각자 볼 수 있는 정보는 다를 수 있습니다. 다른 참가자의 이번 답은 제출 전에 가리고, 추가 검토까지 끝난 뒤 최종 답을 모아 규칙에 정해진 범위만 공개합니다.

잔디 깔기의 타일 배치에서는 한 사람의 행동이 끝날 때마다 공원판을 갱신해 다음 참가자에게 넘깁니다. 미스터리 거래소에서는 한 라운드를 가상 5분으로 나누고, 매분 참가자마다 행동 기회를 한 번 줍니다. 대화하거나 이동하는 차례에도 주문을 낼 수 있으며, 주문이 체결되면 현금과 보유량을 즉시 갱신합니다.

## 6. 전략 메모와 추가 검토는 어떻게 기록하나요?

전략 메모는 참가자가 행동과 함께 제출한 짧은 설명입니다. 추가 검토를 지원하는 단계에서는 모델이 임시 답안과 다시 확인할 점을 적고 검토를 요청할 수 있습니다. 유효한 임시 답안을 바탕으로 한 번 더 모델을 호출하고, 새 답이 유효하면 그 답을 사용합니다. 공통 실행기의 동시 선택에서는 검토 답이 유효하지 않으면 임시 답을 유지합니다.

미스터리 거래소의 한 플레이에서는 참가자들이 후자전자의 **매수량**을 상승 조건으로 보고 주문을 맞췄습니다. 실제 조건은 전체 **보유량**이었습니다. 웹에서 참가자를 고른 뒤 **생각과 검토**의 메모와 **대화와 행동**의 주문 기록을 보면, 어떤 가설로 주문했고 이후 공개된 단서와 어디서 어긋났는지 확인할 수 있습니다.

## 7. 이전 매치에서 어떤 정보를 이어받나요?

매치를 이어서 실행할 때는 완료된 `events.jsonl`을 읽어 생존자 명단과 보유 피스를 가져옵니다. 감옥 매치는 직전 메인 매치의 감옥동 배정 명단으로 시작합니다. 2일차 메인 매치는 1일차의 메인 매치와 감옥 매치 결과를 함께 읽고, 두 매치의 탈락자를 제외합니다. 페르소나는 같은 참가자 ID로 다시 불러옵니다.

친밀도와 신뢰도는 평가한 사람과 평가받은 사람의 쌍마다 가장 최근 값을 가져옵니다. 예를 들어 P01이 P02에게 매긴 점수와 P02가 P01에게 매긴 점수는 따로 저장합니다. 새 매치에서도 참가자는 자신이 본 대화와 행동을 근거로 점수를 갱신할 수 있습니다. 미스터리 거래소에서는 4라운드마다 평가 기회가 있고, 갱신한 점수는 이후 행동을 요청할 때 모델에 전달합니다.

## 8. 저장된 플레이는 웹에서 어떻게 재생하나요?

엔진은 발언, 이동, 선택, 점수 변화가 생길 때마다 `events.jsonl`에 한 줄씩 추가합니다. Python 웹 서버는 작성이 끝난 줄만 읽어 브라우저에 전달합니다. React 화면은 선택한 기록까지 이벤트를 순서대로 적용해 당시 판세와 참가자 위치를 복원하고, 세트장을 Canvas로 그립니다. 진행 중인 시뮬레이션은 브라우저가 주기적으로 기록을 다시 읽어 따라갑니다.

**구간 이동**에서 규칙 공개나 협상 시작처럼 보고 싶은 장면으로 건너뛸 수 있습니다. **관전 시점**은 화면에 표시할 기록의 범위를 바꿉니다. 운영자 시점에서는 전체 기록을, 공개 시점에서는 모두에게 알려진 기록을, 참가자 시점에서는 해당 참가자가 볼 수 있었던 기록을 표시합니다.
